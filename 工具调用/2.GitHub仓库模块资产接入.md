# GitHub 接入手册（上册：从零到登录成功）

> 由 2026-10-27 一次完整实战会话沉淀（安装 → 授权三次失败 → 最终成功）。 适用 Windows（PowerShell 5.1）；Linux/Mac 差异见括号内备注。 配套下册《github-inventory》：登录成功后如何拉取、阅读、呈现仓库清单。

## 0. 正确的道路（决策流程图）

```
1. 检测: gh auth status 成功?  ──是──> 接入完成，转下册拉清单
2. gh 未安装? ──是──> 装 gh（§2），装到纯英文路径
3. 未登录:
   首选路线A: 用户手里已有/能生成 PAT ──> gh auth login --with-token（最稳，§3.1）
   备选路线B: 设备流 gh auth login -w ──> 仅当网络稳定时用（§3.2，易死在最后一步）
4. 登录后: 网络自检（§4）→ 转下册
```

**核心经验：能走 PAT 就别走设备流。** 浏览器通道几乎总是稳的，终端通道（尤其过代理）很脆——把"人在浏览器点几下"的成本花在最关键的一步（生成 token）上，之后的 `--with-token` 只需一次普通 API 调用即可完成。

## 1. 环境检测

```
gh auth status          # 已装且已登录 → 显示账号 + scopes + keyring 字样
gh --version            # 仅检测是否安装
```

常见安装位置（找不到但用户说装过时按序找）：

- Windows: `%LOCALAPPDATA%\Programs\GitHubCLI\bin\gh.exe`、`C:\Program Files\GitHub CLI\gh.exe`、自定义盘如 `D:\Tools\GitHubCLI\bin\gh.exe`
    
- Linux/Mac: `/usr/bin/gh`、`/usr/local/bin/gh`、`/opt/homebrew/bin/gh`
    

参考实况：gh 装在纯英文路径（如 `D:\Tools\GitHubCLI\bin\gh.exe`），典型 scopes 为 `repo, gist, read:org, workflow`，构建机可能未装 git。

## 2. 安装 gh（未装时）

```
# 首选 winget（需要可用的话）
winget install GitHub.cli

# winget 不可用 → 官方 zip 便携安装（无需管理员）：
# 1) 查最新版: GET https://api.github.com/repos/cli/cli/releases/latest 取 *windows_amd64.zip 的 browser_download_url
# 2) 下载 → Expand-Archive → 拷到 D:\Tools\GitHubCLI（纯英文路径！）→ zip 内结构是 bin\gh.exe（没有版本子目录）
# 3) 加入用户 PATH:
$userPath = [Environment]::GetEnvironmentVariable("Path","User")
[Environment]::SetEnvironmentVariable("Path", "$userPath;D:\Tools\GitHubCLI\bin", "User")
```

**教训**：

- 智能体沙箱里 `Start-Process` 弹交互窗口会报 `0x800700e8`（ERROR_NO_DATA）——这不是用户机器坏了。路径含中文也可能触发。对策：交互式环节让用户自己双击脚本/开终端跑；全自动环节用后台任务抓输出。
    
- gh 的 zip 解压后顶层就是 `bin\gh.exe`，不要找 `gh_x.y.z_windows_amd64\` 子目录。
    

## 3. Token 获取

### 3.1 路线A：PAT（强烈推荐）

**给用户的保姆级指引（原话可直接发）**：

1. 打开这个链接（已预填权限）： `https://github.com/settings/tokens/new?scopes=repo,gist,read:org,workflow&description=gh-cli-local`
    
2. Expiration 选 **7 days**（安全）；点底部绿色 **Generate token**
    
3. 复制 `ghp_` 开头的字符串发给智能体
    
4. 智能体执行登录：
    

```
# token 先写入文件再管道给 gh，避免出现在命令行参数里
# 注意用 ASCII 编码写（PS 默认 UTF-8 带 BOM 会污染 token 首字符！）
Set-Content -Path "$env:TEMP\tok.txt" -Value $token -Encoding Ascii
Get-Content "$env:TEMP\tok.txt" | gh auth login -h github.com --with-token
Remove-Item "$env:TEMP\tok.txt"
```

- `--with-token` 会联网调 `GET api.github.com` 校验 token——**必须包重试**（见 §4）
    
- 失败报 `error validating token: ... EOF` = 网络问题，不是 token 问题
    

### 3.2 路线B：设备流（备选，坑多）

```
gh auth login --hostname github.com --git-protocol https --web
```

流程：显示 8 位码（15 分钟有效）→ 回车开浏览器 → `https://github.com/login/device` 输码 → Authorize。

**三次失败换来的教训**：

1. **授权网页显示成功 ≠ 本地登录成功**。gh 可能在"用码换令牌"的最后一步被网络掐死（EOF），令牌没落地。验证方式：看 `%APPDATA%\GitHub CLI\hosts.yml` 是否生成（Linux/Mac: `~/.config/gh/hosts.yml`），只有 `device-id` 没有 `hosts.yml` = 白授权了，重来。
    
2. **轮询进程会被智能体沙箱清理**。前台命令结束，等待用户授权的 gh 子进程跟着死。对策：把"启动 gh + 抓设备码 + 轮询 hosts.yml"整体放进 `run_in_background` 的持久任务（上限 10 分钟，够用）。
    
3. **抓设备码别用 PowerShell 的 `2>&1 | Out-File`**——stderr 会被包成空的 ErrorRecord 把授权码吞掉。对策：用 .NET `System.Diagnostics.Process` + `BeginErrorReadLine` 事件写文件，或直接放弃设备流改走 PAT。
    
4. 全自动设备流可以绕过 gh 自己实现（client_id 用 gh 公开的 `178c6fc778ccc68e1d6a`，POST `github.com/login/device/code` + 轮询 `github.com/login/oauth/access_token`），每步 HTTP 都带重试就不怕闪断。仅在前两条路都死时才值得写。
    

### 3.3 Token 权限（scopes）速查

|scopes|能干什么|
|---|---|
|`repo`|读私有仓库、推代码、建/改仓库内容|
|`read:org`|读组织信息（gh 登录校验需要它）|
|`gist`|管理代码片段|
|`workflow`|推送 GitHub Actions 工作流|
|`delete_repo`|删仓库（**默认别给**，要删仓库时临时加）|

## 4. 网络规程（每个 gh 调用都必须遵守）

常见情况：直连和代理（如系统代理 `127.0.0.1:8080`）**都可能间歇性失败**，POST 比 GET 死得勤，代理对终端程序尤其不可靠（EOF/空响应），而浏览器走自己的通道一直正常。

**诊断（30 秒定位）**：

```
$curl = "C:\Windows\System32\curl.exe"
& $curl --noproxy "*" -sI -m 12 https://api.github.com/zen      # 测直连
& $curl -x http://127.0.0.1:8080 -sI -m 12 https://api.github.com/zen   # 测代理
```

**重试协议**（直连/代理交替 + 退避，可直接抄；下册所有命令都基于它）：

```
function Invoke-GhRetry {
    param([string[]]$GhArgs, [int]$Max = 6)
    for ($i = 1; $i -le $Max; $i++) {
        if ($i % 2 -eq 0) { $env:HTTPS_PROXY = "http://127.0.0.1:8080"; $env:HTTP_PROXY = "http://127.0.0.1:8080" }
        else { Remove-Item Env:HTTPS_PROXY -ErrorAction SilentlyContinue; Remove-Item Env:HTTP_PROXY -ErrorAction SilentlyContinue }
        $out = & gh @GhArgs 2>&1
        if ($LASTEXITCODE -eq 0) { return ,$out }
        Start-Sleep -Seconds (2 * $i)
    }
    throw "gh failed after $Max attempts"
}
```

## 5. Token / 配置存放位置

|内容|Windows|Linux/Mac|
|---|---|---|
|gh 登录配置（哪个账号、协议）|`%APPDATA%\GitHub CLI\hosts.yml`|`~/.config/gh/hosts.yml`|
|token 本体|Windows 凭据管理器（auth status 显示 keyring）|macOS 钥匙串 / Linux libsecret|
|用户级 gh 配置|`%APPDATA%\GitHub CLI\config.yml`|`~/.config/gh/config.yml`|
|临时替代|环境变量 `GH_TOKEN` / `GITHUB_TOKEN`（优先级最高，会覆盖已登录账号）|同左|

- 查看/导出当前 token：`gh auth token`（谨慎：打印明文）
    
- 换账号：`gh auth login` 再来一次即可，多账号用 `gh auth switch`
    
- 撤销 token：网页 GitHub → Settings → Developer settings → Personal access tokens → Delete
    

## 6. 故障速查表

|症状|原因|解法|
|---|---|---|
|`error validating token: EOF`|登录校验请求被网络掐断|重试 §4 协议，别怀疑 token|
|网页授权成功但 `auth status` 说未登录|gh 在保存前被 EOF/进程清理杀死|查 hosts.yml；直接改走 PAT|
|`accepts at most 1 arg(s), received N`|PS 5.1 把含引号的参数拆碎了|去 `--jq`，用 `--json` + `ConvertFrom-Json`|
|token 用不了/校验失败但格式正确|token 文件带 BOM 或含换行|用 `-Encoding Ascii` 重写，`.Trim()` 后再管道|
|Start-Process 报 `0x800700e8`|沙箱不允许弹交互窗口/中文路径|交互步骤交给人；自动步骤用后台任务|
|push 要求登录弹窗|git 装了但没接 gh 凭据|`gh auth setup-git`|
|速率限制 403|未认证 60 次/小时|确认走的是登录后的 gh（5000 次/小时）|

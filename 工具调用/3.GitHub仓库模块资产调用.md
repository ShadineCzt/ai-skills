# GitHub 清单手册（下册：拉取、阅读、呈现）

> 前提：gh 已安装且已登录（`gh auth status` 通过）。没登录先翻上册《github-connect》。 所有命令都套上册 §4 的 `Invoke-GhRetry` 重试函数（本册 §7 有完整副本，两册各自可用）。

## 0. 三层清单体系（总纲）

|层级|拿到什么|命令|何时用|
|---|---|---|---|
|**L1 仓库总清单**|账号下全部仓库的元数据|`gh repo list --json ...`|一切分析的起点|
|**L2 仓库结构清单**|单仓库完整目录树（文件+目录路径）|`gh api .../git/trees/main?recursive=1`|判断每个仓库"里面有什么"|
|**L3 文件内容清单**|单个文件/README 的内容|`gh api .../contents/...` ／ readme|判断模块"具体是干嘛的"|

工作流固定为 L1 → L2 → L3：先全量扫描，再对可疑/重点仓库下钻，最后读关键文件。

## 1. L1 仓库总清单

```
$json = (Invoke-GhRetry @("repo","list","--limit","200","--json",
  "name,owner,description,isPrivate,isFork,primaryLanguage,updatedAt,diskUsage,pushedAt")) -join "" | Out-String
$repos = $json | ConvertFrom-Json
```

**字段怎么读**：

|字段|含义|阅读要点|
|---|---|---|
|`name` / `owner.login`|仓库名 / 归属|命名高度雷同的要标记疑似重复（如 `a_b`、`a-b`、`b-a`）|
|`description`|仓库描述|判断定位的第一线索；为空则只能靠 L2/L3 推断|
|`isPrivate`|私有/公开|私有关乎报告里的脱敏提醒|
|`isFork`|是否 fork|fork 来的仓库内容不是用户写的，单独标注|
|`primaryLanguage.name`|主要语言|**空值很常见**：空仓库或纯文档仓库就是 null，别当异常|
|`updatedAt` / `pushedAt`|元数据更新 / 代码最后推送|pushedAt 才代表"最后一次真推代码"|
|`diskUsage`|体积 KB|0 = 空仓库实锤|

## 2. L2 仓库结构清单（文件树）

```
$tree = (Invoke-GhRetry @("api","repos/OWNER/REPO/git/trees/main?recursive=1")) -join "" | Out-String | ConvertFrom-Json
$files = @($tree.tree | Where-Object { $_.type -eq "blob" })   # 文件
$dirs  = @($tree.tree | Where-Object { $_.type -eq "tree" })   # 目录
```

**JSON 怎么读**：

- `type: "blob"` = 文件，`type: "tree"` = 目录；只看 `path` 就能还原完整结构
    
- `truncated: true` = 条目超限被截断（巨型仓库），对策：改按一级目录分别拉 `trees/{branch}?recursive=0` 逐层下钻
    
- 分支名不确定时先查默认分支：`gh api repos/OWNER/REPO` → `.default_branch`（常见 main/master）
    
- **空仓库会报 404**，消息是 `"This repository is empty."`——这是正常现象不是故障，直接在报告里标"空仓库"
    
- 壳仓库识别：整个仓库只有 `.gitattributes`（LFS 初始化痕迹）或一行标题的 README，也算空壳
    

## 3. L3 文件内容清单

```
# README 直接读原文（最常用）
$readme = (Invoke-GhRetry @("api","-H","Accept: application/vnd.github.raw","repos/OWNER/REPO/readme")) -join "" | Out-String

# 任意文件：JSON 里 content 字段是 base64
$f = (Invoke-GhRetry @("api","repos/OWNER/REPO/contents/src/main.py")) -join "" | Out-String | ConvertFrom-Json
$text = [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String(($f.content -replace "\s","")))
```

## 4. 怎么"读懂"一个仓库（核心阅读法）

### 4.1 关键标志文件 → 项目类型速查

|看到|就能断定|
|---|---|
|`project.godot` + `*.tscn`|Godot 引擎游戏/应用|
|`package.json`|Node.js / 前端项目（读 `scripts`、`dependencies` 字段知功能）|
|`pom.xml` / `build.gradle`|Java 项目（Spring Boot 看依赖里有没有 `spring-boot-starter`）|
|`requirements.txt` / `pyproject.toml`|Python 项目|
|`*.csproj` / `*.sln`|C#/.NET|
|`go.mod`|Go 项目|
|`index.html` 单文件|纯静态页面|
|`Dockerfile` + `docker-compose.yml`|容器化部署|
|只有 `.md`/文档|笔记/文档仓库|

### 4.2 目录惯例 → 模块用途推断

|目录/文件|通常用途|
|---|---|
|`src/`、`lib/`|核心源码|
|`scripts/`|构建/工具脚本|
|`docs/`|文档|
|`tests/`、`test_*`|测试|
|`assets/`、`static/`、`public/`|静态资源|
|`.github/workflows/`|CI/CD 流水线定义|
|`README.md`|项目自述（定位/安装/用法三要素）|
|`CHANGELOG`、`LICENSE`|版本史 / 开源协议|

### 4.3 推断模块用途的证据链

对每个模块（一级目录/关键文件）给结论时必须写清依据：`用途推断 + 依据（来自文件名/README 第几段/依赖列表）`。证据只有文件名时用"推测"措辞；有 README 或代码佐证时用"确认"。

## 5. 怎么"呈现"给用户（报告规范）

清单报告固定四段式，存成 Markdown 文件交付（不要只贴聊天里）：

```
# GitHub 仓库清单
> 账号 / 生成时间 / 数据来源

## 一、总览表
| # | 仓库 | 可见性 | 描述 | 内容状态 | 最近更新 |
（一行一个仓库，内容状态标注：空仓库/仅XX/完整项目）

## 二、逐仓库详情
### N. 仓库名
- 定位（依据描述/README/文件结构）
- 内容状态（文件数、目录数、技术栈）
- 模块表：| 模块路径 | 类型 | 用途 | 依据 |

## 三、横向发现
（重复仓库、命名混乱、空壳占比、可清理项）

## 四、结论与建议
（下一步：推送备份/删多余/补README，注明所需权限如 delete_repo）
```

**呈现纪律**：

- 探测到的状态要如实标注（如"6 个仓库全是空壳"就说空壳，不脑补模块）
    
- 私有仓库名在公开场合讨论时提醒用户脱敏
    
- 报告末尾附"可随时用本 skill 重新生成"的说明
    

## 6. 后续操作（对清单动手术）

```
gh repo create NAME --private                          # 建空仓库
gh api -X DELETE repos/OWNER/REPO                      # 删仓库（token 需 delete_repo scope）
gh auth setup-git                                      # git 用 gh 凭据（推送前一次即可）
# 推送备份：cd 项目 → git init → add → commit → remote add origin → push -u origin main
```

## 7. 附：Invoke-GhRetry 完整副本（自包含）

```
function Invoke-GhRetry {
    param([string[]]$GhArgs, [int]$Max = 6)
    # 直连/代理交替重试；系统代理地址（示例 127.0.0.1:8080）请按自己的环境修改
    for ($i = 1; $i -le $Max; $i++) {
        if ($i % 2 -eq 0) { $env:HTTPS_PROXY = "http://127.0.0.1:8080"; $env:HTTP_PROXY = "http://127.0.0.1:8080" }
        else { Remove-Item Env:HTTPS_PROXY -ErrorAction SilentlyContinue; Remove-Item Env:HTTP_PROXY -ErrorAction SilentlyContinue }
        $out = & gh @GhArgs 2>&1
        if ($LASTEXITCODE -eq 0) { return ,$out }
        Start-Sleep -Seconds (2 * $i)
    }
    throw "gh failed after $Max attempts"
}
```

**传参铁律（PowerShell 5.1）**：传给 gh 的参数不能含内嵌双引号（会被拆碎），禁用 `--jq '<带引号表达式>'`，一律 `--json` 拿原始数据后 `ConvertFrom-Json`。
